# SPEC.md — Perkins WritingSpace MVP 規格

狀態:草案 v0.1(2026-09-29)｜依據:`PROTOTYPE.md`、兩份研究報告
用途:實作前的範圍、技術選用與驗收標準。實作中發現與本文衝突時,先改本文再改程式。

## 0. 產品原則(2026-10-07)

功能取捨與實作細節不得違反以下原則;違反時先改本節(須作者同意),再改功能。理論依據見 `docs/Agentic Writing 與 Harness Engineering：Fundamental Theory、架構與護欄.md`。

1. **作者擁有最終決定權**:AI 是協作者,不是作者。稿件與 Canon 的任何改動都由作者明確接受(G1、G2)。
2. **提案取代直接修改**:AI 只能提出可回溯的提案,不能寫入(G1、G3)。
3. **三種真實性層級不混用**:Canon = 作者確認的事實;Draft = 目前的稿件;Interpretation = AI 對作品的推論(分析、對話內容、整理出的偏好)。Interpretation 永遠不會默默升格為 Canon;要升格必須經提案由作者接受(G2、B6)。
4. **能由程式確定的事不交給模型猜**:權限、上下文預算、名稱比對、快照、檢查等可確定的工作一律由程式執行(G4)。
5. **送出內容看得見**:送給模型的每一項內容都能預覽並看出來源(A6、G4)。
6. **作品資料可攜**:正文、設定、大綱、筆記保持普通檔案(Markdown + frontmatter),不用 Perkins 也能讀;`.perkins/` 只放程式與 Agent 的中繼資料。
7. **Bot 弱人格、強工作身份**:Perkins Bot 不演有個性的聊天角色,重點是清楚自己在這部作品中的規則、權限、上下文與作者偏好。
8. **以真實寫作驗收**:每輪大改(尤其 Perkins Bot、編輯器、版面)完成後,除自動化驗證外,由作者實際寫一個場景或一章;作者開始想切到別的工具的地方,就是下一輪的優先問題。

## 1. MVP 目標

一句話:**能拿來寫自己的小說,且 AI 在技術上無法未經同意改動任何文字或設定。**

MVP 成功的判斷不是「AI 寫得多好」,而是:
- 作者能在裡面連續寫作,不需離開去別的工具。
- AI 只能讀與提案;所有改動都經過作者明確接受。
- 任何一次接受都可回到接受前的狀態。

## 2. 範圍

### 2.1 護欄範圍(核心四項)

對應研究報告的十道護欄,MVP 只做以下四項,其餘明列為非目標。

| # | 護欄 | 對應原文 | MVP 具體行為 | 為什麼重要(測試要守住的意圖) |
|---|---|---|---|---|
| G1 | 提案非提交 | 命題 2、護欄 2 | AI 的任何修改一律產生 Proposal(目標檔、範圍、基準雜湊、替換文字、理由、假設);作者接受後才寫入 | 防止 AI 偏好悄悄變成作品事實 |
| G2 | Canon 只讀 | 護欄 2、3 | `canon/` 下的設定檔 AI 無寫入路徑,只能提案;AI 只看得到作者本次勾選的設定檔(工具也受限);待審或被拒的 Proposal 永遠不會被當成 Canon 送進上下文 | 防止未批准內容被下一輪當成既定事實 |
| G3 | 版本與回溯 | 命題 6、護欄 9 | 每次接受 Proposal 前自動快照;作者可手動快照;可看 diff、可還原;每次接受寫入 Provenance 記錄 | 防止錯誤累積且無法回復,並能辨識人類貢獻 |
| G4 | 工具與權限白名單 | 護欄 5、6 | AI 只能呼叫白名單工具;拒絕的呼叫也留紀錄;單次對話迭代次數有上限;送出前可預覽將傳給模型的內容 | 防止越權與稿件外流,防止代理無限循環 |

### 2.2 功能範圍
- 專案(資料夾)開啟/建立、章節檔案樹、Markdown 編輯。
- Canon 編輯:作者自己維護角色、世界觀、時間線等設定檔(純 Markdown)。
- 右側 AI 對話框;選取段落後右鍵「詢問 AI」。
- Proposal 審核介面:行內 diff、接受/拒絕、附理由與假設。
- 快照清單、diff、還原。
- 模型設定:OpenAI 相容端點(涵蓋 LM Studio、OpenAI、OpenRouter 等)。

### 2.3 非目標(MVP 不做,並記錄原因)
- 不確定性介面、澄清問題閘、多候選並列:第二階段,待實際使用後看是否需要。
- 多樣性檢查、Embedding、分支管理:依賴重,價值需先靠使用驗證。
- 多角色 Agent(Orchestrator、Reviewer 等):MVP 只有單一唯讀助手,角色分離留待連貫性檢查 Agent 出現時。
- Anthropic 原生 API adapter:OpenAI 相容端點先滿足;需要時再加。
- Intent Ledger、Source Ledger、PerkinsBench:研究層產物,非原型阻塞項。
- 匯出/發布、雲端同步、多人協作。

## 3. 技術選用

| 層 | 選擇 | 理由 / 取捨 |
|---|---|---|
| 桌面框架 | **Wails v2.12**(Go + WebView2) | 本機已安裝;體積小;強制邏輯放 Go 側,前端無法繞過。風險:WebView2 版本差異;若中文輸入法或右鍵選單出問題再評估 Electron |
| 前端 | React + TypeScript + Vite | Wails 官方模板支援;shadcn/ui 生態 |
| UI | shadcn/ui + Radix + Tailwind | 沿用 `PROTOTYPE.md` |
| 編輯器 | **CodeMirror 6**(純 Markdown)+ `@codemirror/merge` | 稿件即純文字檔;內建行內 diff 可直接顯示 Proposal;較 ProseMirror/TipTap 不需處理富文本與 Markdown 的往返轉換。**待驗證**:中文 IME 組字行為 |
| 模型接入 | OpenAI 相容 `/v1/chat/completions`(串流 + tool calls) | 一套 adapter 涵蓋 LM Studio 與雲端。本機 LM Studio 已可用(localhost:1234) |
| 儲存 | 專案資料夾:Markdown + JSON;快照為專案內內容定址檔(不依賴使用者裝 git) | 稿件可用任何工具開啟、可備份、不被鎖定 |
| API 金鑰 | 系統憑證庫(Windows Credential Manager),不寫入專案資料夾 | 避免金鑰隨稿件被備份或分享 |

**強制原則**:G1–G4 全部在 Go 後端執行。前端只是呈現;即使前端有 bug 或被替換,AI 仍沒有寫入路徑。

## 4. 專案資料夾結構

```
MyNovel/
  perkins.json            專案設定(名稱、模型設定 id、章節 order;不含金鑰)
  manuscript/             章節,純 Markdown
    01-xxx.md
  canon/                  Story Bible,純 Markdown(AI 唯讀)
    characters.md
    world.md
    timeline.md
  .perkins/
    snapshots/            內容定址快照 + 索引
    proposals/            Proposal JSON(pending/accepted/rejected)
    provenance.jsonl      每次接受/還原的記錄(誰、何時、模型、理由、快照 id)
    audit.jsonl           每次工具呼叫(含被拒絕的)
    research.jsonl        研究記錄(§12.8;預設關閉,開啟才會存在)
```

## 5. 核心模型

**Proposal**
```
id, createdAt, model, target(file), range(start,end), baseHash(目標檔當時雜湊),
replacement, rationale, assumptions[], status(pending|accepted|rejected|conflict)
```
- 接受時比對 `baseHash`;檔案已變動則標 `conflict`,不自動套用。
- `rejected`/`pending` 內容不進入任何上下文的 Canon 區段。

**AI 可用工具(白名單,MVP 全集)**
| 工具 | 效果 |
|---|---|
| `read_document(path)` | 讀 `manuscript/` 或 `canon/` 檔案(唯讀) |
| `search_project(query)` | 專案內全文搜尋(唯讀) |
| `propose_patch(...)` | 建立 Proposal(不寫入稿件) |

沒有寫檔、刪除、網路、shell 工具。任何不在名單的呼叫 → 拒絕並寫入 `audit.jsonl`。
單次對話工具迭代上限預設 8。到達上限即停止工具迴圈(硬上限):寫入 `iter_limit` 審計、發一則 notice 告知作者,再送一次**不提供任何工具**的收尾請求,告訴模型已達工具呼叫上限,請它就目前已知的內容回答作者,並說明停在哪裡、還缺什麼。收尾回覆當正常回覆處理(寫入對話歷史與研究記錄);收尾請求本身失敗(含取消)照錯誤路徑處理,不重試;模型仍回傳工具呼叫時忽略呼叫、只取文字內容。

**上下文組裝**(確定性程式,不交給模型判斷):目前文件 + 選取範圍 + 作者勾選的 Canon 檔;送出前可預覽,雲端端點首次使用需顯示外流警告。

## 6. 介面(對應 PROTOTYPE 構想)

- 左:專案檔案樹(manuscript / canon 分區,canon 標示「AI 唯讀」)。
- 中:編輯器;選取文字右鍵 →「詢問 AI」。
- 右:對話框;AI 產生 Proposal 時,對話中顯示卡片,中間編輯器以行內 diff 呈現,附「接受 / 拒絕」。
- 底部或側欄:版本清單(快照、diff、還原)。
- 清爽為原則:預設只顯示編輯器與收合的對話框。

## 7. 驗收標準(以意圖為準,非只測行為)

每項標明**破壞它時會失去什麼**,測試必須在該意圖被破壞時失敗。

| ID | 標準 | 破壞後果 |
|---|---|---|
| A1 | 無論模型輸出什麼內容(含試圖呼叫不存在工具、要求寫檔),`manuscript/` 與 `canon/` 檔案雜湊在作者按「接受」前不變 | G1 失效,AI 可靜默改稿 |
| A2 | 檔案在提案後有變動時:原文仍原封不動且唯一 → 重新定位套用,作者在別處的編輯完整保留;原文被改動或不再唯一 → 標 `conflict`、不寫入 | 作者新寫的字被 AI 舊提案蓋掉 / 作者在別處打字就讓所有提案失效 |
| A3 | `pending`/`rejected` Proposal 的內容不出現在後續請求的上下文中 | 未批准內容變成事實 |
| A4 | 每次接受都先產生快照;還原後檔案雜湊與接受前一致 | 出錯後無法回復 |
| A5 | 白名單外工具呼叫被拒並出現在 `audit.jsonl`;超過迭代上限即停止工具迴圈,只回一次不帶工具的收尾回覆 | 越權與無限循環無痕跡 |
| A6 | 送往模型的內容與預覽顯示的一致(不含未勾選的 Canon 檔) | 使用者以為沒送出的稿件外流 |
| A7 | 金鑰不出現在專案資料夾任何檔案 | 金鑰隨稿件外洩 |
| A8 | 以 LM Studio 本機模型完成:開檔 → 選取段落詢問 → 收到 Proposal → 接受 → 還原,全程可用 | MVP 的核心迴圈跑不通 |
| A9 | 人工驗證:實際寫一章,中文輸入法(組字、選字)在編輯器中無異常 | 主要使用情境不可用 |

## 8. 風險與待驗證

1. **本地模型 tool-calling 品質**:qwen 類模型對 `propose_patch` 的參數遵循度不穩。備案:改為要求模型輸出結構化 JSON,由 Go 解析後建立 Proposal(G1 不受影響)。里程碑 M2 先驗證。
2. **CodeMirror 6 中文 IME**:於 M1 儘早人工驗證,不通過則評估替代編輯器。
3. **Wails/WebView2 行為**:自訂右鍵選單、大檔捲動效能,M1 驗證。
4. **護欄過度規訓**(研究報告 §9):MVP 護欄只管「誰能寫入」,不做文學層面的自動評判,避免誤判刻意的歧義或違規。

## 10. 已決定事項
- **章節排序**(2026-09-29 決定):順序存於 `perkins.json` 的 `order` 陣列(檔案相對路徑清單),介面可拖曳調整,調整只改 `order`、不改檔名。原因:快照、Provenance、Proposal 都以路徑為鍵,改檔名會使歷史對不上。
  - 新增章節預設附加在 `order` 尾端。
  - 存在於 `manuscript/` 但未列入 `order` 的檔案:依檔名排在尾端並提示。
  - 列在 `order` 但檔案不存在的項目:忽略並提示,不自動刪除。
  - MVP 為單層清單,不做卷/部巢狀;若寫作中需要,列入 M5 調整清單。
  - 驗收:拖曳排序後所有檔案雜湊不變、`order` 更新;重開專案順序保持。
- **第二階段優先順序**:作者無偏好。暫定順序為連貫性檢查 Agent → 不確定性/澄清 → 多樣性檢查,M5 實際使用後再依痛點調整。

- **提案衝突放寬**(2026-09-29,作者授權自主決定):見 A2 新版。理由:嚴格版會讓作者在別段打字就使所有舊提案失效;放寬只在「原文完全未動且唯一」時成立,不猜位置。
- **AI 對 Canon 的可見範圍**(同上):`read_document`/`search_project`/`propose_patch` 對 `canon/` 只限本次勾選的檔案;稿件不受限。理由:讓「預覽送出內容」確實等於 AI 能看到的設定,保護作者尚未想讓 AI 知道的伏筆。
- **編輯器內行內 diff**:暫不做,以提案卡片的原文/替換對照代替;M5 使用後再評估。
- **快照儲存**:MVP 以「完整檔案副本」實作,未做內容定址去重。長篇多次快照會佔空間,M5 視實際大小再改。

## 12. 範圍

### 12.1 作品結構
- **卷 → 章 → 場景**。卷只存在 `perkins.json`(`volumes: [{title, chapters: [路徑]}]`),不搬檔、不改檔名(沿用 §10 理由)。舊專案的 `order` 自動視為單一未命名卷。場景 = 章節內的 `##` 標題,由程式解析,可在側欄跳轉。
- **章節狀態**:草稿/完成,存 `perkins.json`。
- **大綱** `outline/`(全書概要、各卷大綱,自由 Markdown)與**筆記** `notes/`(作者私人)。
- **字數**:狀態列顯示本章/本卷/全書字數(不含 Markdown 記號與空白)。

### 12.2 設定集結構化
- `canon/` 下每個設定檔是一個「實體」,以 YAML frontmatter 記錄程式需要的欄位:`type`(角色/地點/勢力/道具/名詞/其他)、`name`、`aliases`。其餘描述(口癖、稱呼、外貌…)留在本文,作者自由書寫。沒有 frontmatter 的舊檔視為 `type: 其他`、`name` = 檔名。
- **自訂分類**(2026-10-06):內建分類之外,作者可在設定集側欄的「管理分類」新增自訂分類;清單存作品內 `.perkins/categories.json`,跟著作品走。自訂分類可刪除、內建不可刪。刪除仍有設定檔的分類:先彈確認對話框(告知會有幾個設定檔改歸「其他」),確認後自動建立快照(G3),再把這些檔的 frontmatter `type` 改成「其他」(`name`/`aliases`/本文不動,檔案不刪);沒有設定檔的分類直接刪。名稱需去空白、非空、不與既有分類或「大綱」「筆記」「略過」重複、不含路徑字元。自訂分類會出現在所有選分類的地方:設定集側欄分組與新增設定的類型選單、EntityHeader 類型選單、Notion 匯入「匯入為」選單(前端 TARGETS 與 Go 端 target 驗證)。這是作者自己的操作、不是 AI:AI 工具白名單不變,G2/G4 不放寬(AI 不能新增或刪除分類)。
- **自訂分類的健壯性**(2026-10-06 返工定案):
  - **刪除前先存檔**:前端按下確認刪除時,先走既有的序列化存檔迴圈(等在途存檔、保存未存內容);存檔失敗就中止刪除並顯示錯誤,不動任何檔案。存檔成功後才快照與改型(快照因此含作者最新內容);完成後若開啟中的檔案受影響,從磁碟重新載入(此時無未存內容,不丟字),後續存檔不會把舊 type 寫回。
  - **批次改型要原子**:後端先備好全部新內容再逐一寫入;任一寫入失敗就把已寫的檔案寫回原內容再回報錯誤;回復也失敗時,錯誤訊息列出受影響路徑與快照名稱。清單以暫存檔＋rename 寫入;清單寫入失敗同樣回復已改的檔案。前端失敗分支也要重讀分類與索引,畫面反映實際狀態。
  - **清單損毀不當空清單**:`.perkins/categories.json` 只有「檔案不存在」才視為空清單;讀取或解析失敗回傳錯誤,介面顯示並阻止新增/刪除(不得覆蓋原檔),作者才有機會修復。
  - **清單同步**:所有分類清單消費者共用同一份狀態,新增或刪除後全部重讀;已開啟設定檔的 EntityHeader 類型選單立即出現新分類。
  - **刪除在途要擋住中斷**(2026-10-06 第二輪):刪除流程(存檔→刪除→重讀)進行中,管理分類對話框不可關閉(Esc、外點、關閉鈕都無效)、確認鈕停用並顯示「刪除中…」——對話框是 modal,關不掉就擋住編輯與切檔。套用重讀內容前確認目前開啟的檔案仍是該路徑,不是就不套用。刪除成功但重讀失敗:關閉目前檔案(回到未選檔狀態)並顯示錯誤請作者重新開啟——此時沒有未存內容(刪除前已存檔),舊 buffer 不得再存回舊 type。
  - **分類快取綁定作品**(2026-10-06 第二輪):共用分類狀態以作品路徑為識別;切換作品時清空並重新查詢,以世代計數忽略上一作品的在途結果——A→書櫃→B 後側欄與 EntityHeader 只顯示 B 的分類。附帶:Notion 匯入遇到不認得的去處時不得靜默跳過,要列入略過報告並附原因(Go 端)。
- **登場索引**:程式掃描稿件中的名稱與別名,列出每個實體在哪些章節出現幾次;章節也列出本章登場實體。
- **寫法不一致檢查**(確定性):找出與已知名稱只差一個字、且本身不是已知名稱的寫法(如「艾麗絲」vs「艾莉絲」),列給作者判斷,不自動修正。只對 3 字以上名稱做,降低誤報。
- **附加建議**:選取段落或目前章節中出現的實體,在對話框顯示為「建議附加」,作者點選才附加。

### 12.3 AI 協作
- **附加檔案泛化**:對話框以標籤呈現附加內容(目前文件、選取段落、任何專案檔)。取代原本的勾選清單。
  `canon/`、`outline/`、`notes/` 維持「只有附加的才看得到」(工具也受限);`manuscript/`、`summaries/` 可自由讀。大綱可能含未寫到的劇情,筆記是私人內容,所以與設定同級保護。
- **多端點與模型切換**:設定頁管理多個端點設定檔(本機 LM Studio、雲端…),各自的金鑰存系統憑證庫;對話框可切換端點與模型。切換到遠端端點時,本次啟動內需重新確認外流警告。
- **部分採用**:提案卡片的建議文字可先編輯再接受。Provenance 記錄 `authorEdited` 與最終文字,以區分人類貢獻。
- **提案審查視窗**(2026-10-10,#35):提案卡的「放大審查」(圖示+tooltip)開一個可拖曳、可調整大小(CSS `resize`)的懸浮視窗,層級在 Perkins Bot 浮窗之上。標題列:目標檔名、`第 i / n 個`、上一個/下一個(在目前待審提案間切換)、模型名、關閉。內容左「原文」(唯讀)、右「修改後」(可編輯),**視窗自己**寬度 < 720px 時改上下堆疊(不是螢幕寬度);下方顯示理由與假設,衝突狀態照卡片同一套文案與停用規則。預設 `min(900px,92vw)`×`min(640px,85vh)` 置中,開啟與視窗縮放時限制回可見範圍(同 §17.3 浮窗規則)。編輯內容與聊天卡片**共用同一份狀態**(兩邊互相反映),接受/拒絕呼叫同一組流程(G1/G3:只有作者明確點擊才會寫入;唯讀鎖、快照、Provenance 用語不變);處理完一張接清單上的下一個待審提案,已是最後一個就關閉。`Esc` 只關閉視窗,不改變提案狀態;聊天窗內原本的卡片與接受/拒絕保留不變。
- **快速指令**:右鍵選單「快速指令」子選單(與「詢問 Perkins Bot…」並列;選取浮動列「段落指令」同樣可用):分析這段/檢查是否違反設定/節奏/接下來的合理發展。帶入問題後由作者按送出(可先調整附加內容)。
- **一致性檢查(報告模式)**:本次請求**不提供** `propose_patch` 工具,AI 只能輸出檢查報告,由作者決定改什麼。
- **章節摘要**:AI 草擬 → 作者在對話框中編輯 → 儲存才生效,存於 `summaries/`(frontmatter 記錄來源章節與其雜湊)。章節改動後摘要標示「可能過期」。未儲存的草稿永遠不進上下文(延伸 A3)。
- **分層上下文**:設定原文(不壓縮)+「前情摘要」(本章之前已確認的章節摘要)+ 目前章節全文 + AI 以工具查原文。
- **對話壓縮**:對話歷史超過端點上下文長度(設定頁可調)的預算時,程式先請模型把較早對話濃縮成摘要,並在對話中顯示通知;預覽顯示的即為實際送出的內容。預算計算由程式執行。

### 12.4 輸出
- **複製為平台格式**:章節一鍵複製到剪貼簿。規則:段首縮排(無/兩個全形空格)、段落間空行、標題處理、強調記號去除、場景分隔符號、繁簡轉換(不轉/轉簡體字/轉簡體含詞彙)。
- 內建角角者、巴哈姆特、輕之國度、菠蘿包、Penana 預設,介面標示並可自行修改。角角者已由作者實際貼上確認可用(2026-10-10,#29);其餘四個**未經實際貼上驗證**。
- 詞彙級轉換會改變作者用詞,預設只做字形轉換,詞彙轉換需作者選擇。
- **整卷匯出 `.txt`**:套用同一組規則。
- 輸出只寫剪貼簿或作者指定的匯出檔,不動稿件。

### 12.5 Notion 一次性匯入
- 讀取 Notion「Markdown & CSV」匯出的資料夾或 zip:去除檔名中的 Notion id、內部連結轉純文字、依資料夾分組,由作者為每組指定設定類型(或略過/匯入為筆記),寫入 `canon/` 或 `notes/` 並補上 frontmatter。
- 同名檔案不覆蓋,列入報告。匯入前自動快照。之後不再與 Notion 連動。可在資料夾之下逐頁覆寫去處或略過。展開資料夾後,逐頁清單整齊排在該資料夾列下方、欄位對齊且不重疊(不得變成重疊在「匯入為」選單下方的內捲動框;2026-10-06 修正)。

### 12.6 介面(shadcn/ui)
- **啟動畫面**:程式名稱、美化按鈕、下方以**書櫃**呈現最近開啟的專案(清單存在應用程式設定目錄,不在專案內)。封面可自選圖片,未選則依書名自動產生。
- **主畫面**:最左側圖示列(稿件/設定集/大綱與筆記/檢查),點選開啟可收合的側欄;**齒輪固定在圖示列左下角**,開啟設定頁。右側為可收合的資訊欄(本章登場、摘要、實體登場索引)。
- **設定頁**:模型端點、平台輸出規則、專案(名稱、封面)、外觀。
- **AI 對話**:右下角懸浮圓鈕 → 可拖曳、可調整大小的浮動對話框。輸入區包含附加標籤、📎 附加、模型切換、👁 預覽、送出。提案卡片在對話框內顯示。
- 版本改為對話視窗(Dialog)。

### 12.8 研究記錄(研究模式)

- **目的**:記錄作者的操作與 AI 的行為,作為研究資料。粒度「中等」:記錄作者的操作事件、送給 AI 的完整內容、AI 的回覆與工具呼叫、耗時;**不**記錄逐次打字的稿件變化。
- **開關與預設**:**預設關閉**。作者在設定頁(作品分頁)手動開啟;開關存在 `perkins.json` 的 `research` 欄位,隨作品走。
- **檔案位置與格式**:開啟後以 JSON Lines 逐行 append 到作品資料夾內的 `.perkins/research.jsonl`;**另開新檔**,`audit.jsonl`、`provenance.jsonl` 完全不動。每筆共同欄位:`ts`(RFC3339 含毫秒)、`event`、`session`(App 啟動時產生的隨機 id,區分不同使用時段),其餘欄位依事件而定。關閉時不建立任何檔案。
- **記錄的事件**:`ask`(model、profile 是否 remote、mode、doc、selection 字數、attachments、summaries、sent(前置失敗未送出時 false)、requests(依序列出每次**實際送出**的請求快照與該次回覆,含 ask 與 compact 兩種用途;達迭代上限後的收尾請求(不帶工具)也是一筆 ask;compact 請求另記 `ok` 表示壓縮是否成功套用,失敗也記錄但標 `ok:false`),AI 最終回覆、工具呼叫清單、本次建立的 proposalIds、耗時、結果 ok/error/cancelled/iter_limit(iter_limit = 到達工具迭代上限、但已由收尾請求回覆;收尾請求本身失敗則照一般錯誤記 error/cancelled);§16 第 21 項:問題來自快速指令(右鍵選單、選取浮動列、檢查面板)時另記 `quickId`(快速指令 id)與 `quickEdited`(布林,作者送出前改過快速指令帶入的問題文字;不記改前全文,沿 §12.8 不額外記錄原則),非快速指令來源不寫這兩個欄位);`proposal_accept`(proposal id、target、是否作者修改、原 replacement,作者修改時另記 final、耗時)與 `proposal_reject`(proposal id、target、耗時)分開記錄;`save`(path、存檔前後字數以 CountText 計算,不記內文;失敗時記 ok=false 與 error,不記 afterCount);`snapshot`/`restore`(label/id、檔案清單);`summary_draft`(chapter、耗時)/`summary_save`(chapter);`copy_chapter`/`export_volume`(章節/卷、平台 id);`open_file`(path)。
- **不記錄**:逐次打字的稿件變化;`save` 與 `open_file` 只記路徑與字數,不記內文(ask 例外:作者主動送出的內容本來就會送給 AI,故記錄完整 messages)。
- **與 audit/provenance 的關係**:完全獨立。`audit.jsonl`(工具呼叫審計,G4)與 `provenance.jsonl`(接受/還原溯源)照舊,研究記錄不擴充也不取代它們。
- **隱私**:只存這台電腦;開啟後檔案會含送給 AI 的稿件片段與 AI 回覆,研究記錄不在 AI 的上下文中,AI 工具也讀不到 `.perkins/`。研究記錄的寫入失敗不中斷作者的操作。

## 15. 第二階段實作時代為決定的事項(2026-09-30,作者可推翻)

- **刪除 = 移到回收區**:章節、大綱、筆記的刪除都是搬到 `.perkins/trash/<時間>/`,不真正刪除。原因:MVP 原本完全沒有刪除功能,加上後要可回復。
- **場景**:章節內的 `## ` 標題。原因:不需要額外檔案或格式,作者照常寫 Markdown 即可。
- **字數**:標點算字;不計空白、Markdown 記號(`# * _ ~ > | \``)、清單記號與 `<!-- -->` 註解。
- **寫法檢查範圍**:只檢查 3 字以上的名稱/別名、只回報「差一個漢字」且不包含任何已知名稱的寫法;作者可按「不是錯字」加入 `.perkins/variant-ignore.json`。
- **上下文預算**:估算為中日韓字元 1 字 = 1 token、其他約 3 字元 = 1 token;預留 25%(上限 4096)給回覆;對話歷史超過預算 40% 時在回合結束後濃縮(保留最近 2 回合原文)。端點預設上下文長度 16384,可在設定頁改。
- **快速指令不自動送出**:只帶入問題與模式,作者按送出。原因:送出前可以調整附加內容,也符合 A6「預覽 = 實際送出」。
- **雲端外流確認**:每個端點在每次啟動後第一次使用時確認一次(對話與摘要共用)。
- **摘要不接受 AI 提案**:`summaries/` 只能由作者在摘要對話框中編輯與儲存。
- **平台預設**:五個平台都用「兩格全形縮排、段落空一行、場景分隔 ◇◇◇」;簡中平台(輕之國度、菠蘿包)預設只轉字形(tw2s);巴哈姆特保留標題,其他平台不輸出標題。角角者已實際驗證可用(2026-10-10),其餘**未驗證**。
- **整卷匯出不允許存進專案的作者資料夾**,避免匯出檔被當成稿件。
- **Notion 匯入**:圖片不匯入(只告知數量);頁面標題下方的「欄位: 值」屬性轉成條列;依資料夾名稱猜測預設類型(含「角色」「地點」等字樣),其餘預設匯入為筆記,作者可逐組修改。
- **封面**:存在 `.perkins/cover.*`(上限 4MB),書櫃讀取專案內的封面;最近專案清單存在 `%APPDATA%\Perkins\settings.json`。
- **技術**:Go 套件 `export` 改名為 `publish`(`export` 是 TypeScript 保留字,Wails 生成的綁定無法編譯);shadcn/ui 元件集中在 `components/ui/{button,basic,overlay}.tsx` 三個檔案,而不是一個元件一個檔。

# UI_GUIDE.md — Perkins 介面設計指導手冊

狀態:草案(2026-10-13,#97)。標 **【現行】** 的條目已是規格或現有程式的做法,只是集中寫下;標 **【草案】** 的條目是本手冊新提出的統一規則,作者定案後改標【定案】。

## 0. 適用與地位

- 所有介面新增與改版都依本手冊。Reviewer 審查介面變更時,以標【現行】【定案】的條目為準;【草案】條目只供參考,違反不列為阻擋問題。
- 本手冊只管「長什麼樣、怎麼互動」;功能行為、護欄與驗收以 `docs/SPEC.md` 為準。兩者衝突時以 SPEC 為準,並回頭修正本手冊。
- 基礎是現有介面已形成的慣例,不重新設計。要偏離本手冊,先在 Issue 說明理由並由作者決定,再改手冊、再改程式。
- 不為了符合手冊而大規模改寫既有畫面;既有不一致列在 §14,隨相關修改逐步收斂。

## 1. 設計語彙 【現行】

「夜間書房」:深色主題以深藍墨色為底、琥珀金(書脊燙金)為強調色;淺色主題為暖白紙張。作者的文字(稿件、原文、提案內容)用明體,介面用黑體。介面讓位給文字:裝飾少、強調色只用在需要作者注意或採取行動的地方。

## 2. 色彩

- 【現行】只用 `style.css` 定義的語意色彩變數(Tailwind 對應名稱):`background`、`foreground`、`sidebar`、`rail`、`paper`、`card`、`popover`、`primary`、`secondary`、`muted`、`accent`、`border`、`input`、`ring`、`destructive`、`success`、`warning`。程式中沒有直接寫死的色碼,維持如此。
- 【現行】深淺兩個主題都必須成立;新增變數要在 `:root` 與 `.dark` 同時定義。
- 【草案】用途:
  - `primary`:主要動作、選中狀態、焦點。一個區塊最多一個主要按鈕。
  - `warning`:需要作者留意但非錯誤(雲端外流、摘要可能過期、檢查報告模式、不可復原的提醒)。
  - `destructive`:錯誤訊息與破壞性操作的確認鈕。
  - `success`:已驗證、已儲存等正面狀態,只當標示,不當按鈕。
  - 淡底提示框:`border-warning/40 bg-warning/10 text-warning`(與 Badge 的 warning 同一組)。
- 例外:書櫃自動產生的封面可用計算出的色值(封面是作品的圖像,不是介面元件)。

## 3. 字體與字級

- 【現行】字體:介面 `font-sans`(Segoe UI、微軟正黑體);作者的文字與作品相關標題用 `font-serif`(思源/Noto 明體)。
- 【草案】字級只用以下幾級,不再寫 `text-[13px]` 這類任意值:

  | 級別 | 類別 | 用途 |
  |---|---|---|
  | 說明 | `text-xs`(12px) | 說明文字、中繼資料、標籤、狀態列、工具列提示 |
  | 內文 | `text-sm`(14px) | 介面主要文字、表單、清單項目、對話內容 |
  | 區塊標題 | `text-lg`(18px)+ `font-serif font-semibold` | 設定頁區塊、對話框標題 |
  | 頁標題 | `text-xl` 以上 | 書櫃、設定頁頁首,一個畫面最多一個 |

  作者文字的大小由稿紙版面設定決定,不在此表。
- 【草案】字重:標題 `font-semibold`、強調 `font-medium`;`font-bold` 只用於封面。
- 【草案】側欄標題、清單中的作品文字(原文摘要、檔名)用 `text-sm`;目前用 13/15px 的地方併入 `text-sm`,10/11px 併入 `text-xs`(見 §14)。

## 4. 間距與圓角

- 【現行】間距以 Tailwind 4px 刻度為準;同一容器的間距單一來源(用父層 `gap-*`,不在子元素疊加 `mt-*`,SPEC §17.2)。
- 【草案】間距層級:控制項之間 `gap-1`–`gap-2`;同一群組內的列 `gap-3`–`gap-4`;群組與群組之間 `gap-6`–`gap-8`。群組之間的距離必須大於群組內,讓相關的東西看得出是一組。
- 【草案】圓角:按鈕、輸入框、清單列 `rounded-md`;卡片、區塊容器、浮窗 `rounded-lg`;圓形頭像或膠囊 `rounded-full`。不再新增裸 `rounded`、`rounded-xl`。

## 5. 元件

- 【現行】按鈕、輸入框、開關、勾選框、徽章、對話框、選單、下拉、提示、分頁一律用 `src/components/ui/` 的元件,不各自重寫樣式。缺的元件先加到 `components/ui/`,再使用。
- 【草案】按鈕變體:

  | 變體 | 用途 |
  |---|---|
  | `default` | 區塊的主要動作(儲存、送出、接受) |
  | `outline` | 次要動作(取消以外的並列選擇) |
  | `secondary` | 低強調的並列動作 |
  | `ghost` | 工具列、圖示按鈕、清單內的小動作 |
  | `destructive` | 破壞性操作的**確認**那一步 |
  | `link` | 句中的連結式動作 |

- 【草案】按鈕大小:面板、側欄、浮窗內用 `sm`;工具列圖示用 `iconSm`;`default`/`lg` 只用在書櫃、設定頁等大面積頁面。
- 【草案】原生 `<button>` 只用於「整列或整張可點」的清單列、卡片、樹狀節點;其他一律用 `Button`。
- 【現行】圖示用 lucide;尺寸 `h-3 w-3`(徽章內)、`h-3.5 w-3.5`(說明列、小標)、`h-4 w-4`(按鈕內,`Button` 已預設)。
- 【草案】只有圖示的按鈕必須有 `Tip`(提示文字),說明它做什麼。

## 6. 狀態與回饋

- 【現行】錯誤不吞、不靜默:顯示在發生的地方附近(例如表單下方、對話框錯誤列),用 `text-destructive`。
- 【現行】自動行為(自動存檔)成功時只更新狀態,不跳提示框;作者主動的操作才給結果回饋(SPEC §17.3)。
- 【草案】狀態標示用 `Badge`(`warning`、`success`、`secondary`),不自己拼樣式。
- 【草案】空狀態寫一句說明這裡會放什麼、怎麼開始,不放插圖。
- 【草案】停用的控制項要說明原因(提示或旁邊一行字),例如「至少要保留一個端點」。

## 7. 確認與破壞性操作

- 【現行】不使用瀏覽器的 `confirm()`/`alert()`。
- 【現行】破壞性或不可復原的操作用**同一位置兩步確認**:第一次按下後,原地出現說明後果的一行字與 `destructive` 確認鈕(例:對話記錄「永久刪除 → 永久刪除後無法還原/確定永久刪除」、版本「確定要還原?」)。
- 【草案】可復原的操作(封存、移到已刪除、可由快照還原的接受)不需要確認。
- 【草案】需確認時,說明文字寫出具體後果,不寫「確定嗎?」。

## 8. 介面摩擦與治理等級 【草案,依 SPEC §0 第 10 條】

介面要求作者操作的程度,對應 Agent 能力的治理等級:

| 等級 | 介面表現 |
|---|---|
| 自由 | 不出現任何確認或事先挑選的步驟 |
| 看得見 | 事後可查:可展開的記錄列、清單、研究記錄;預設收合,不打斷作者 |
| 確認一次 | 第一次使用時在發生處顯示 `warning` 提示框與勾選,確認後記住、不再出現 |
| 每次核准 | 由專門的審查畫面處理(審查視窗);卡片與通知只負責告知與開啟,不在多處各自做決定 |

不得為了「比較安全」在前兩級加入確認對話框或要求作者先挑選內容。

## 9. 覆蓋層與視窗

- 【現行】設定頁是覆蓋整個作品畫面的頁面(上緣接標題欄)。
- 【現行】Perkins Bot 對話與提案審查視窗是可拖曳、可調整大小的浮窗;審查視窗層級在 Bot 浮窗之上(SPEC §12.3)。
- 【草案】`Dialog` 用於需要作者專心完成的短任務(新增、改名、版本、摘要);長時間並行使用的工具用浮窗或側欄,不用 Dialog。
- 【草案】一個操作最多疊一層 Dialog,不在 Dialog 裡再開 Dialog。

## 10. 版面與寬度

- 【現行】640 寬(半螢幕)是最小支援寬度:任何畫面都不得出現水平捲軸,長文字截斷或換行(SPEC §17.1、§17.3)。
- 【現行】捲動只發生在內容區;頁首、導覽欄、工具列固定(SPEC §17.2)。
- 【現行】頁面內容限制最大寬度並置中(設定頁 `max-w-5xl mx-auto`)。
- 【草案】清單與表單在窄寬度下用同一套版型,控制項換到下方即可,不另做一套窄版介面。

## 11. 用語

- 【草案】介面用繁體中文;稱作者為「你」,稱 AI 為「Perkins Bot」(空間不足時「Bot」)。
- 【草案】按鈕寫動詞(「儲存」「接受」「附加」),不寫「確定」「OK」;說明一句話講完。
- 其餘用語一致性與去除 AI 腔,見 #28。

## 12. 設定頁 【草案,依作者提供的優良案例與 #97】

參考案例:作者提供的 Codex 桌面版設定頁截圖(2026-10-13,「一般」「個人化」「外觀」「外觀 › 進階」四張),對照 #97 整理的 Microsoft、Apple、GNOME、JetBrains、VS Code 做法。

### 12.1 結構

- 層級固定為**導覽頁 → 區塊 → 設定列**,所有頁共用同一個 `Section` 與同一種設定列元件,不再各頁自寫。
- **頁標題**:內容區最上方一個大標題(`text-xl` 以上,與導覽項目同名)。
- **區塊**:區塊標題(`text-sm font-semibold`)放在卡片**外面**上方,下面是一張圓角卡片(`rounded-lg border`),卡片內的設定列以分隔線隔開(GNOME 的 boxed list、Codex 的做法)。區塊之間留大間距(`gap-8`),區塊內各列緊貼、只靠分隔線。
- 區塊需要整體範圍切換時(例如「全域/目前作品」),切換器放在區塊標題列右側。
- 導覽欄:圖示+文字,選中項目用填色圓角背景標示。頁數少(目前 4 頁),不做搜尋與群組標題;頁數明顯增加時再議(YAGNI)。

### 12.2 設定列

- 左邊**名稱**(`text-sm font-medium`)+ 下方一行**說明**(`text-xs text-muted-foreground`,可省略);右邊**控制項**,垂直置中。窄寬度時控制項換到名稱下方。
- 控制項依選項種類:

  | 選項 | 控制項 |
  |---|---|
  | 開/關 | 開關 |
  | 2–3 個互斥選項 | 分段按鈕(例如「系統/開啟/關閉」) |
  | 4 個以上,或選項名較長 | 下拉選單 |
  | 數值 | 數字輸入框+單位(例如「14 象素」);有明確範圍且需要即時感受時用滑桿+數值 |
  | 路徑、檔案 | 縮短顯示的路徑+「變更」按鈕 |
  | 外觀類的選擇 | 有預覽圖的選擇卡,選中有明顯外框 |
  | 長文字(AGENTS.md、說明) | 不放在列內;做成「進入子頁」的列(見 12.3) |

- 單一動作(刪除記錄、重設)也是一列:名稱+說明寫出後果,右側是動作按鈕;破壞性動作用 `destructive` 淡色按鈕,按下後依 §7 兩步確認。
- 有風險的開關,說明直接寫出開啟後的後果(例如雲端外流會傳送哪些內容)。
- 說明中需要延伸閱讀時,句末加「了解更多」連結,不把長說明塞進列內。
- 停用的列整列變淡,並在說明中寫出原因(§6)。

### 12.3 子頁與集合

- 【定案,2026-10-12】**集合類設定(端點、平台)用卡片清單+子頁**:設定頁只有一條側欄;清單放在內容欄內,每項一列(名稱、狀態、結尾「›」,整列可點),點擊推入該項目的子頁,子頁上方有返回鍵與項目名稱;「新增」「從預設新增」入口在清單上方;刪除在子頁內、要確認;640 寬用同一套。
- **進入子頁的列**:結尾「›」、整列可點,用於長文字或內容多的單一設定(例如作者指示 AGENTS.md:列上寫名稱與一句說明,點進子頁才是編輯區)。
- 開啟外部頁面的項目,結尾用「↗」而不是「›」。

### 12.4 進階與重設

- 少用、會讓作者困惑的選項收進頁面底部的「進階」可展開區(預設收合),不另開頁。
- 頁面有「重置為預設值」時,放在「進階」同一列的右側,低強調的文字按鈕;重設前依 §7 確認。

### 12.5 套用方式

- 開關、分段按鈕、下拉、選擇卡**即時生效**,不放「儲存」鈕。
- 多欄位表單(端點子頁)與長文字(AGENTS.md 子頁)按「儲存」才寫入;有未儲存變更時要顯示狀態,離開子頁前提醒。
- 同一個畫面不混用兩種方式:即時生效的列和要按儲存的表單不放在同一張卡片裡。

## 13. 驗收

- 【現行】介面變更須實際 render 檢查畫面與互動(AGENTS.md),深淺兩個主題都看;寬度至少看 640 與 1280,設定頁另看 900(SPEC §17.2)。
- 【現行】E2E 依改動挑選測試組(`.agent/skills/e2e/SKILL.md`,例如設定頁版面 `settings-layout`、半螢幕 `layout-half`)。
- 【現行】可被測試操作的元素加 `data-testid`,名稱用小寫加連字號(例:`bot-read-section`)。

# Alpha 早期公測決策(#157)

- 日期:2026-10-27
- 狀態:**待作者決定**。本文件是評估與建議;評估階段不建立 release、tag 或 CI workflow。
- 與會:Codex(Issue 指定主導)、DeepSeek(Pi)、Max(Claude Code,主持與彙整)。開了兩輪:各自獨立評估,再交換報告互評。

## 一句話結論

**現在先不宣布 Alpha。** 先花約 2–3 個工作日補齊「發佈準備」,再加上作者 1–2 小時的實際寫作驗收,通過後就以 **Windows 免安裝 ZIP、少數受邀測試者** 的方式開始 Alpha。

程式本身的基礎已經夠用:Go 測試、`go vet`、前端型別檢查都通過,三條硬線(未經作者接受不改稿、改了能復原、未確認不送雲端)都有既有測試支持。缺的是發佈相關的準備,以及在別人電腦上實際跑一次的證據。

## 兩方的共識

- **門檻不是「待辦清空」**,而是三件事:三條硬線守得住、別人的電腦能正常開起來、出問題能回報與追查。
- **第一版只發 Windows 免安裝 ZIP**(執行檔 + 說明 + 授權 + 檢查碼)。不做安裝檔、自動更新、程式簽章、多平台。
- **CI 只放基本檢查,E2E 先不上 CI**。現行 E2E 在本機要開 `wails dev` 的視窗、會讀寫作者的設定檔、寫死 Edge 的路徑(`app/e2e/lib.js`),測試組之間也有先後依賴,現在搬上 CI 不划算(GitHub 主機能不能跑 `wails dev` 未實測)。
- **發佈檔一律從指定的 main 提交重新建置**。不使用現有的 `app/build/bin/perkins.exe`,它是 10/25 建的,已經落後 main。
- **不另開 CHANGELOG 檔**。Release 說明直接從 `docs/PROGRESS.md` 整理成使用者看得懂的文字,並寫上設定搬移等相容性事項。
- **可以延後的**:#28 / #158 介面打磨、#154 提示詞研究、#115 長期記憶、#41、#29、E2E 上 CI、程式內「回報問題」按鈕。**#161(表格顯示不正常)有條件延後**:先確認只是顯示問題、不影響編輯與存檔,才可延後;若影響編輯或存檔就列為阻擋。(DeepSeek 認為 Issue 內文已定位在 Bot 回覆的顯示;Codex 認為標題指向稿紙化、發生位置仍待確認,不能就此定案。)
- **測試綠燈不等於安全審計**。DeepSeek 做過有限的搜尋(常見金鑰樣式、歷史提交裡有沒有加入過敏感檔名),沒有命中;Codex 核對了相關的程式邊界與測試,沒有做金鑰或歷史掃描。雙方同意這只能說明「沒找到」,不能說成「已確認安全」。

## 兩方的分歧與我的建議

1. **版本號叫 `v0.2.0-alpha.1` 還是 `v0.3.0-alpha.1`?**
   - Codex 主張 0.2.0:SPEC 裡 0.2.0 對應的是第二階段規格,沒必要為了公測升一版。
   - DeepSeek 主張 0.3.0:這一輪有使用者看得到的改動,而且 Windows 執行檔的版本欄位會顯示 `0.3.0`,跟 tag 名字比較對得上。
   - **我的建議:`v0.2.0-alpha.1`**。DeepSeek 擔心的是「名稱對不上」,只要必做第 2 項讓程式內顯示完整版本(例如 `0.2.0-alpha.1 (提交編號)`),測試者回報就不會混淆。之後再發 alpha 就是 `alpha.2`、`alpha.3` 往上加。這是產品語意的選擇,由作者決定。
2. **公開 Release 還是私下傳連結?**
   - DeepSeek 傾向不公告、只私下給測試者連結。Codex 第一輪就建議公開的預發行版、少量招募,並提醒公開倉庫的 Release 即使只私下給連結,任何人仍抓得到;第二輪再澄清「不公告」不等於「有存取控制」。
   - **我的建議**:公開放在 GitHub Release,標成預發行版本,只邀請少數人試用,說明裡寫清楚「這是公開可下載的測試版」。程式裡沒有需要保密的東西,真正要保護的是測試者的稿件,這靠公測說明和 Issue 表單處理。若作者希望真正受控,就不要用 GitHub Release,改用私下傳 ZIP 檔。
3. **「已經達到 Alpha 條件」可以講多肯定?**
   - DeepSeek 第一輪說「程式本身已經夠格」,Codex 認為證據不夠。雙方第二輪收斂成:**程式層的證據足以準備候選版本,但要通過乾淨電腦實測和作者實際寫作驗收(必做第 6、7 項),才算可以開放。**

4. **Alpha 期間要不要凍結新功能?**
   - DeepSeek 主張凍結到 Alpha 結束;Codex 主張沿用目前的克制方針,不另外宣布凍結。
   - **我的建議**:不另外宣布凍結。目前方針本來就是「沒有作者明確需求的新功能不主動做」,效果接近凍結;正式宣布反而會擋住作者自己想加的小東西。

## 需要作者決定的事

1. **要不要照上面的門檻開 Alpha**,邀請多少人、邀請誰。
2. **版本號**:建議 `v0.2.0-alpha.1`。另一個選項是 `v0.3.0-alpha.1`。
3. **怎麼分發**:建議放公開的預發行 Release、只邀請少數人。另一個選項是私下傳 ZIP,真正受控。
4. **安全問題怎麼私下回報**:email、GitHub 的私下安全回報功能,或其他方式。這只有作者能指定。
5. **支援範圍**:Windows 版本與架構(例如 Windows 10/11 64 位元)、哪些模型、哪些輸入法算已驗證。沒驗證過的輸入法,不宣稱支援。
6. **Alpha 期間的工作方針**:建議沿用目前「克制改善、Bot 穩定性優先」的方針,先處理資料完整性和 P0/P1 問題,不另外宣布功能凍結或固定發版週期。
7. **第一輪的成功條件**:建議是「少數測試者能完成實際寫作與提案回溯,沒有未解決的資料遺失或越權外送,嚴重問題都有處置」,達到之後再考慮擴大。不以「收到幾個 Bug」作為指標。

## 還需要實測才知道的

- 免安裝 ZIP 在乾淨電腦上的實際情況:Windows 安全警告長什麼樣、沒有 WebView2 時會怎樣。
- 真實模型的核心流程(Bot 工具呼叫 #34、拒絕後重提)。這兩次評估都沒有實際跑。
- 第一次上 CI 時,前端依賴的鎖定檔是否乾淨:CI 用 `npm ci`,正式建置用 `npm install`,兩者可能不一致。

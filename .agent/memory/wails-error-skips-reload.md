# 已寫入磁碟的操作不要以錯誤回給前端:Wails 回錯時前端拿不到回傳值、不會重載稿件

- **觸發條件**:後端綁定(接受提案、還原快照等)已經改了磁碟上的稿件,之後的步驟(來源紀錄、提案狀態)失敗,或檢查到稿件被外部改過而沒套用,於是回傳 `error`。
- **證據**(2026-10-19,PR #136、#140 的 Codex 審查,各有 E2E/Go 測試重現):Wails 綁定回錯時 JS Promise 直接 reject,前端進 catch、跳過 `onAccepted`/`onRestored` 的重載,finally 又解除編輯鎖。編輯器仍是舊內容且顯示已儲存,作者接著打字或自動存檔,整份舊內容寫回磁碟,剛還原/套用的稿件或外部的修改就消失。破壞驗證(PR #136 E2E U3b):Restore 改回回錯時「編輯器已重載」「存檔不帶回舊稿」兩項 FAIL,實際把舊稿寫回。
- **做法**:
  - 已寫入:回傳成功,用只回給介面、不存檔的欄位說明沒完成的部分(`recordError`),前端照成功路徑重載後再顯示警告。
  - 沒寫入但磁碟已被外部更新:回傳成功並帶說明欄位(`notApplied`),前端在編輯鎖內只重載(不標示改動)再提示。
  - 能調整順序就先讓「記錄」成功再寫稿(#140 先存提案狀態再寫稿),失敗時什麼都沒寫、照常回錯即可;只靠記憶體補救的狀態在切換作品或重開後會消失。
  - 研究記錄等呼叫端要分辨「成功但沒套用」,不能只看 `err == nil`。
- **適用範圍**:所有會寫作者檔案、且前端在成功後重載編輯器的 Wails 綁定。純讀取或失敗時磁碟完全沒變的錯誤照常回錯。
